# 指标导出正确性与抓取开销设计

## 范围

本项只调整 `internal/metrics` 的 Prometheus 文本导出及其测试，
保留既有指标名称、标签维度、请求统计 API 和 nil receiver 行为。
不增加第三方依赖，不提交，不替换运行中的服务。
后续分别设计 TTFT 计时口径与预算生命周期，本项不修改这两个模块。

## 已核查的问题

1. 内部请求计数以 backend/model/status 为键；导出请求数保留 status，
   但 token 指标省略 status，因而同一 backend/model 不同状态生成重复
   标签样本，且每条只是分状态的 token 数，不能表达正确总量。
2. Render 在持有请求热路径共用锁时排序请求键。现有输出写入已在锁外，
   不将写入阶段误认为持锁；需要移出的只是排序与其他派生计算。
3. Render 忽略 fmt 写入错误，始终返回 nil，导致上层无法发现抓取失败。

## 方案与备选

采用最小导出修复：锁内复制独立快照，解锁后排序，再按 backend/model
聚合 token，并将导出错误传回调用方。请求数仍按状态分别导出，
token 指标每个标签集只出现一次。

备选一是给 token 加 status 标签，但改变现有标签契约，且该维度
不属于文档中 token 总量语义，本项不采用。
备选二是直接分片锁或重构所有内部计数；目前没有实际竞争测量，
且不能单独解决重复样本，本项不采用。并发基准后再判断是否需要分片。

## 快照与输出

锁内复制请求计数、inflight、waits、rejects 和两个直方图；
计数器为值拷贝，直方图桶必须独立复制，避免导出读到仍在写的切片。
解锁后按原 backend/model/status 顺序排序请求样本，
同一 backend/model 的样本归并为一条 token 总量。
其他指标及其稳定排序保持不变。

输出可使用标准库 bufio.Writer 缓冲 fmt 写入，
最终 Flush 返回底层错误；遇到底层错误时缓冲器保留错误状态，
后续写入不能将失败覆盖为成功。nil Registry 不进行任何写入。
保持 Prometheus 帮助文本、类型、毫秒直方图桶及 +Inf 语义。

## 测试与验收

先在旧实现复现两个行为失败：不同 status 的 token 必须汇总且唯一；
底层写入失败必须由 Render 返回。
再实现最小修复，覆盖多个 backend/model 的独立汇总、
输出稳定顺序、包含特殊字符的标签、零 token 与短写错误。
并发更新与反复抓取时，race 检查必须通过，最终统计精确，
每次抓取的指标名与标签组合唯一，直方图保持一致。

新增单线程抓取和并发记录/抓取基准，记录旧实现与新实现的
ns/op、B/op、allocs/op。若总导出耗时因为正确聚合有所增加，应如实报告；
不预设性能提升百分比，也不将压力微基准当真实推理吞吐提升。
运行 metrics 回归、全量 race、vet、构建、文档链接与 diff 格式检查。
